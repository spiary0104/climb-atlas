# Languages (i18n) — owner guide

Today: English (default, fallback) and Simplified Chinese (zh-CN). Code: `js/modules/i18n.js`; strings:
`i18n-en.js`, `i18n-zh-CN.js`; guard tests: `tests/i18n.test.js`. How it works: `docs/ARCHITECTURE.md` (i18n bullet).
Gym data (names, addresses, visitor notes) is never translated; it is shown as stored.

## a) Add a language (e.g. ja)
1. Copy `js/modules/i18n-en.js` to `i18n-ja.js`; translate every value. Keys, `{placeholders}` and plural shapes stay identical
   (plural objects need `other`; Japanese/Korean/Chinese only need `other`, but keep one/other if English has them).
2. `i18n.js`: add `'ja': () => import('./i18n-ja.js')` to `LOADERS`; set `enabled: true` on its `LOCALES` row (flip it last).
3. `sw.js`: add `js/modules/i18n-ja.js` to `SHELL_FILES` and bump `CACHE_VERSION`.
4. `tests/i18n.test.js`: add the language to the complete-dictionary test (`[['zh-CN', ZH], ['ja', JA]]`) and to the
   enabled-languages assertion.
5. Review checklist: native reviewer read every screen (Explore, filters, gym page, check-in, passport, log, add, report,
   /mod, sign-in, toasts, offline banner); no English left in the UI (aria-labels, placeholders, `<option>`, `document.title`,
   map controls: see the scan in "Audit" below); text fits at 375 px (no clipping in chips, tab bar, buttons); numbers/dates
   look right; `matchLocale` maps the browser language; the language picker lists it under its own name.
Audit: in the browser, in the new language, list `[aria-label],[title],[placeholder]` and `<option>` values that contain
Latin letters only; each should be a brand, an abbreviation or gym data.

## c) SEO
- Today: one URL per page, English only. `api/seo.mjs` renders English titles, descriptions and JSON-LD server-side; the app
  retitles in the browser after load (zh-CN when chosen). No `hreflang`, no language in URLs, one sitemap.
- Recommendation: do not index per-language URLs until the translations are reviewed and a page's content is really
  translated (gym names/addresses stay original, so a "Chinese page" is mostly chrome).
- Later options, in order: `/zh/` path prefix + `hreflang` alternates (en, zh-Hans, x-default) + per-language sitemap entries,
  only for pages with real translated content (home, region and city pages first). No thin machine-translated pages. Server
  meta (`seo-meta.js`) already accepts a translator (`tr`), so the titles are ready.

## d) Google Play listing (when the TWA exists)
- Translate per language: app title (30 chars), short description (80), full description (4000), screenshots (one set per
  language, taken from the localised app: `i18n-shots` style 375 px captures), feature graphic text if any.
  Play locale code for Simplified Chinese: `zh-CN` (`zh-TW` for Traditional).
- Owner decision: Google Play is not available in mainland China. Mainland Android users need other stores (e.g. Huawei,
  Xiaomi, Tencent app stores) or the web app/PWA; each has its own review and, usually, a company and ICP requirement.
  Not researched yet.

## e) Android / TWA notes
- Manifest (`manifest.json`) has name, short_name, start_url `/index.html`, scope `/`, standalone, theme/background colours,
  192/512 icons, a 512 maskable icon, and now `lang: en`, `dir: ltr`. The manifest has one language: the app UI language is
  chosen at runtime.
- A TWA still needs: `/.well-known/assetlinks.json` (package name + signing-key SHA-256, served as `application/json`
  without redirects); a Bubblewrap project (`bubblewrap init --manifest https://www.bouldeer.com/manifest.json`) with
  the same host, a signing key, Play App Signing fingerprint added to assetlinks; an icon set Play accepts (512 px, maskable
  present); Digital Asset Links verified, otherwise Chrome shows the URL bar.
- A TWA runs in Chrome's profile for the origin: `localStorage` (the `bouldeer_lang` choice), service worker and caches work
  as in the browser. `navigator.languages` follows the Android system/app locale, so first-visit detection works; a manual
  choice persists and wins. Clearing Chrome site data resets it.
- Sign-in: Google/magic-link redirects must return to the TWA origin; test on a device before publishing.

## f) Next languages
- **zh-TW**: start from zh-CN by an automatic conversion (OpenCC-style, with Taiwan phrasing: 影片/軟體/網路 etc.), then human
  review of every screen. Never machine-only. Needs `matchLocale` to route zh-TW/HK/MO/Hant (already refuses to map them to
  Simplified), the `html` code `zh-Hant-TW`, and the glossary above reviewed for Taiwan climbing terms.
- **ja, ko**: translate the dictionary; gyms already carry `name_local` (shown with the English name). Place labels are
  the larger job: `js/modules/place-names.js` needs Japanese prefecture/city and Korean province/city labels (today
  region/city names come from English data and `regions.js`). Check Noto font loading for CJK, line-breaking in chips, and
  date/number formats (Intl handles them).
- **de, fr, es, pt-BR**: plurals matter (`one/other`, French `one` includes 0, Portuguese `many`); longer strings need a
  layout pass at 375 px; all four exist in `LOCALES` as disabled.
- Always: human review, then the audit, then flip `enabled`.

## Known gaps (not fixed yet)
Place names in the UI (cities, regions, "Shanghai" in `· Shanghai`, region pages) are English from data/`regions.js`;
legal pages (privacy, terms, about) are English only; the offline banner appears only on the data-fallback path;
`placeholder="you@example.com"` and state abbreviations (NSW, VIC) are intentionally unchanged.
