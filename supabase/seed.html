Boulder Atlas — one-time seed

Loads every spot from js/data.js and upserts them into your Supabase spots table. Safe to run more than once — it matches on id, so re-running just re-syncs the seed rows rather than duplicating them.

This needs your project's service_role key, not the public anon key. The moderation policy in schema.sql deliberately only lets the public anon key insert spots as status = 'pending' (so a random visitor can never insert a pre-approved row) — but this seed script writes rows straight in as already-approved, which is exactly what the service_role key is for: it bypasses row-level security entirely, the same way the Supabase SQL Editor does.

Get it from Dashboard → Project Settings → API → service_role (secret). Never put this key in js/supabase-init.js or any file that ships to visitors — paste it below only, run this page locally from your own machine, and never deploy this file to a public host.

Before clicking the button: run supabase/schema.sql in your Supabase SQL Editor, and make sure js/supabase-init.js has your real project URL filled in (this page reuses that same URL).
